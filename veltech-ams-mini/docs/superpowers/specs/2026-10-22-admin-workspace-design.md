# Administrative workspace and student publication design

Extend the combined application requested by the user; keep version 1.8.0 and existing student academics/results/sync. One shared authenticated login selects a distinct navy/blue admin shell. Owners retain every capability. Limited admins have module and action grants editable after creation, bounded by their grantor, with protected owners and revoked sessions after access changes. Existing legacy module grants remain compatible. A separate admin-account metadata collection and admin access history reference the existing authenticated User/Session rather than duplicating credentials.

Administration reuses existing accounts, academic administration, forms/responses, feedback, notices, calendar/holidays and exam schedules. Add a searchable member directory with role/account status and student academic access links, plus protected admin overview and login history. Official source data remains read-only unless the existing app academic edit permission is used; no university submissions are introduced.

Moderation lists all app posts/reels for authorized reviewers, archives selected content with a required reason, retains audit evidence and creates an owner notification that remains visible after content is removed. A durable mail outbox sends the reason to the owner's legitimate email. No private post content is leaked into other students' notifications.

Event operations add published rules/instructions/contact and acknowledgement at registration. Event managers assign active staff as scanners with separately controlled QR, manual check-in and email privileges. Existing verified payment and atomic ticket check-in stay authoritative. Authorized staff can search participants, mark a verified active ticket manually and send event messages. Students cannot grant access or scan others' tickets.

Messages target active students, all members, an assigned department, event registrants/attendees or explicitly entered external emails. Faculty remain in their department/managed-event scope; admin sends require communications permission. Each recipient receives a separate email; in-app delivery is owner-scoped. Persist campaign/delivery state, deduplicate request retries, claim work atomically, cap batches and retain failed jobs for retry. SMTP absence is shown accurately, never as delivery success.

Exam seating belongs to an existing faculty examination. Authorized staff upload bounded CSV/XLSX or text PDF, preview detected columns/rows, correct entries and explicitly publish. Validate unique VTU IDs, mandatory room/seat and bounded field sizes; reject ambiguous/duplicate input rather than assign guessed seats. Store the original file privately with a release and per-VTU entries. Student lookup derives VTU from verified server-side identity, never a query parameter/social profile; return only that student's row. A matching student may download the published whole attachment as explicitly requested. Withdrawing an exam or seating release revokes visibility/download immediately. Scanned image PDFs require faculty-entered rows because OCR is not configured.

Student exams and admin publications refresh on visible-page polling/focus and retain standard missing-data/error states. Notices, calendar and account changes use existing persistent routes and notification polling. Do not introduce demo records into connected accounts. Keep Atlas, Windows PowerShell, Docker, existing SMTP configuration and private keys. Package the complete project, production web, deployment guide and actual UI preview with no credentials/source captures.
