# veltech-ams-mini V1.4 design

The user has approved autonomous implementation and professional design choices, and explicitly requests this release, ZIP, guide and public preview. Continue within that scope without another design approval pause.

Keep the existing navy, teal and white identity and original logo. Put a prominent current/next class card first on Home; time boundaries are end-exclusive and use Asia/Kolkata. Keep ten official student facts below it. University records are read-only, source-labelled and never exported as a student profile. Social identity is separate: display name, username, bio, social department, links, avatar and privacy do not change official information or authorization scope.

Attendance has an overview calendar, full subject routes, date/status filters, daily source records, conservative target calculations, a student-number calculator with formulas, and PDF/XLSX/CSV exports containing attendance only. Unmarked records are never inferred absent. Events and Community use page routes for creation, registration, tickets, stories and conversations, with Events/Reels tabs and familiar like, save, share and connection controls. Recommendations are transparent scoring rather than a falsely advertised trained model.

Academics shows registered courses, faculty examinations, grades, fees and verified source sections. Remove Resources. Course registration uses discovered AMS data and an official handoff when write integration is unavailable. Placements says Developing until a real source exists. No unavailable portal records or fake official submissions are invented.

Faculty forms support required typed fields, feedback, private proof uploads and scoped review. Conditions include opening/closing time, fixed event position/radius, acceptable accuracy and short-lived one-use submission challenges. Location is supporting evidence and can be spoofed; faculty review remains available. Only persisted faculty/organizer roles in the correct scope may publish or read responses. Students access their own submissions/proofs only.

Settings adds explicit browser permission actions for camera, notifications and location, and separate social preferences. Never request these permissions at startup. Stop test camera tracks immediately, never retain test location. Improve mobile bottom navigation, route loading feedback and reduced-motion support.

Preserve Windows PowerShell + Docker Desktop + MongoDB Atlas workflow. No Ubuntu is required. Ship no runtime keys, university credentials, uploads, real records or node_modules. Test synthetic data locally. Public preview uses fictional data and disables private login/payment.
