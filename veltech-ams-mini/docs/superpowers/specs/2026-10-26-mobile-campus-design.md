# Mobile campus release design

User request: upgrade delivered2.1.0 with faster sync and fixes; top Home next-class area becomes one live reminder hub for current/next class, exams, own seating and staff publications; mobile-first login/settings/notifications; APK-first installation; combined Vel Tech/project branding and opening animation; consistent premium typography; compatible upgrade on AWS behind assumed Cloudflare.

Approach (builder choice under user's standing authorization to choose professional UI): retain React/Vite/FastAPI/campus services and the existing Android Trusted Web Activity packaging, improve their flows instead of migrating frameworks. APK install uses an actually published signed artifact; PWA remains a separate secondary action. An Android browser cannot silently install an APK. Deployment URL and existing signing identity are requested asynchronously, dependent APK work waits for them; app/source improvements continue. No invented deployed URL or credentials, no production AWS writes. No separate admin/faculty login pages.

Design: navy, blue and teal with white surfaces and a pale blue canvas. Root creates a combined campus project emblem using supplied/existing project mark plus publicly available Vel Tech reference, labeled as student app branding rather than an official replacement logo. Self-host Manrope variable font with OFL license; preserve source marksheet PDF typography. One short launch animation per app launch, reduced-motion preference honored, not replayed on polling/navigation; keep saved-session recovery and actual login/CAPTCHA flow intact. Mobile login exposes only logo, fields, verification when required and password recovery; no marketing banner.

Home: replace, rather than append to, LiveClassPin plus separate reminder block. Hero current/next class obeys IST schedule/holiday overrides. Existing24h new-publication /72h near-exam rules preserved. Newly published own seating can announce24h even if exam is older. Hub displays bounded actionable upcoming entries for exams/seating/calendar/semester schedules and audience-filtered staff news; no invented data, no wrong-student visibility. Exact own seat only. No sticky oversized scroll obstruction.

Settings: /settings is a category index on mobile. /settings/:category shows only selected content with Back to settings; desktop retains navigation. Include install/download-update category, existing settings retained. Notifications: readable compact mobile inbox with category filters/date groups, avatars/icons, clear unread state, real mark-read/delete/all-read actions and destinations. Mutations update only affected notification UI and do not reload whole workspace. Owner switches clear optimistic state.

Performance: investigate measured call/render patterns before fixing; preserve owner-scoped cache/logout and backwards compatibility. Coalesce duplicate reads, avoid full snapshots while only sync progress changes, back off on transient failure, pause hidden/offline work. No unsupported guarantee of faster university response times. Keep snapshot freshness visible and service-side limits across concurrent students.

Deployment: retain existing database, private keys and cookies on upgrade. AWS origin behind Cloudflare uses HTTPS Full(strict), restricted trusted proxy selection, no caching private API/session responses and correct public APK attachment delivery (metadata/artifact contain no student data; academic endpoints remain authenticated). Preserve existing signing identity for APK updates; no new signing key silently substituted. Deliver2.2.0 sourceZIP, setup/upgrade guide and browser preview, with actual APK only if public origin and signing prerequisites become available.
