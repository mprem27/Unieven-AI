# Provider configuration

For the complete SMTP setup, branded templates, deployment variables and safe delivery checks, follow [EMAIL-SMTP.md](EMAIL-SMTP.md). For free-hosting constraints and the optional Docker HTTPS tunnel, see [HOSTING.md](HOSTING.md).

Put real values only in `.private/campus.env` generated by Setup.ps1. Preserve quoted env syntax and do not commit this folder. Restart/recreate the campus container after changes. Provider keys must never use the `VITE_` prefix because frontend variables are public.

For real email configure `CAMPUS_MAIL_FROM` plus either SMTP or Brevo:

```dotenv
# Examples are placeholders, not working credentials.
CAMPUS_MAIL_FROM="College events <verified-sender@example.edu>"
SMTP_HOST="smtp.example.edu"
SMTP_PORT="587"
SMTP_SECURE="false"
SMTP_REQUIRE_TLS="true"
SMTP_USER="YOUR_SMTP_USERNAME"
SMTP_PASS="YOUR_SMTP_PASSWORD"
# Alternative: BREVO_API_KEY="YOUR_BREVO_KEY"
```

Use provider-issued credentials and a verified sending domain. Port 465 uses `SMTP_SECURE=true`; port 587 normally uses STARTTLS with `SMTP_REQUIRE_TLS=true`. Certificate verification stays enabled. Do not use the development inbox override for Internet delivery.

For Razorpay configure `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and an independent `RAZORPAY_WEBHOOK_SECRET`. Register the HTTPS `/api/campus/payments/webhook` URL in the merchant dashboard. Use test mode first. Server verification, order identity, amount/currency and webhook state determine paid ticket confirmation.

No real Atlas cluster, SMTP provider, merchant payment or push/SMS provider is bundled. The local development inbox only verifies local application-to-SMTP delivery. The retained academic SMS provider is a logging/unsupported integration unless explicitly implemented and configured; a log entry is not evidence of a sent SMS.
