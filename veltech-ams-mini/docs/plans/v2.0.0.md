# v2.0.0 implementation and acceptance plan

Preserve the combined application, official AMS records, existing grants, tickets,
media and signing identity. Extend the current mobile layout rather than replace it.

1. Share the identity-checked academic session resolver between student and admin
   reads. Test expired/sealed links, concurrent renewal, and cross-owner denial.
   Add separate directory tabs, account pages, permission-shaped records and audit.
2. Dedicated event publishing page: free/paid, rules, poster presentation,
   expiry defaults/custom dates, publish and publish-with-community-post. Expiry
   hides public listings and stops new registration; history/tickets remain.
3. Placement lifecycle and applications: detail page, deadlines, stages,
   authorized applicant review, student status notifications, retained history.
4. Semester schedule publications and home reminders for upcoming exams/own
   seating and published schedules, with upload/download authorization.
5. Explicit storage upgrade: evaluate PostgreSQL document compatibility with real
   API tests before enabling. Never replace an existing database automatically.
   Include verified copy/compare migration and rollback instructions. No claim of
   unlimited free hosted storage.
6. App release metadata and direct APK binary endpoint, installed/version state,
   browser/PWA and Android handoff. Keep the signed-in session; never save the
   password or silently install APKs. Deployment URL/signing configuration remains
   operator-supplied. Clearly record what requires a real signed APK/device test.
7. Version metadata, Windows Docker setup, environment examples, deployment and
   migration guide. Test permissions and workflows, build, inspect mobile/desktop
   with synthetic accounts; export source/web ZIP and a reviewable preview.

Security: server checks every action; grantors cannot escalate their own grants;
student official details stay read-only; audit does not expose credentials/tokens;
no live student data in fixtures/artifacts; no real campaigns during QA.
